## Задание 3: Создание документа «Затраты» и привязка его к регистру накопления

### Цель
Научиться самостоятельно создавать документ с нуля, проектировать под него табличную часть и правильно привязывать его к регистру накопления через настройку движений в конфигураторе.

### Часть 1. Справочник статей затрат (10 мин)

Если ещё не создан — создать справочник **СтатьиЗатрат** с элементами: «Хранение», «Транспортировка», «Порча товара», «Коммунальные услуги», «Прочее».

### Часть 2. Регистр накопления «Затраты» (15 мин)

Создать регистр накопления **Затраты** вида **Обороты**:
- Измерения: `Склад` (Справочники.Склады), `СтатьяЗатрат` (Справочники.СтатьиЗатрат)
- Ресурсы: `Сумма` (число, 15.2)

### Часть 3. Документ «Затраты» (40 мин)

Создать документ **Затраты**:

- **Шапка**: `Дата` (заполняется автоматически), `Склад` (Справочники.Склады), `Ответственный` (строка или ссылка на пользователя)
- **Табличная часть «Расшифровка»**:
  - `СтатьяЗатрат` (Справочники.СтатьиЗатрат)
  - `Сумма` (число, 15.2)
  - `Комментарий` (строка, необязательное поле)

**Привязка к регистру**

1. В конфигураторе открыть документ **Затраты** → вкладка **Движения**.
2. В список регистров, по которым документ может формировать движения, добавить регистр **Затраты**.
3. На вкладке **Движения** конфигуратор автоматически подставит стандартный код обработчика проведения — объяснить студенту, что это заготовка, которую нужно доработать вручную (стандартный код обращается к табличной части документа напрямую, без агрегации).
4. В модуле объекта документа, в процедуре `ОбработкаПроведения(Отказ, Режим)`, вручную написать заполнение движений: цикл по табличной части, для каждой строки — `Движения.Затраты.Добавить()`, заполнить измерения и ресурс.
5. Обязательно указать `Движения.Затраты.Записывать = Истина;` — объяснить, что без этого движения не запишутся в базу, даже если добавлены в коллекцию.
6. Выполнить запрос к табличной части документа с группировкой по Наименованию и суммированием `Сумма`.
7. В цикле по результату запроса проверить каждую агрегированную сумму:
> если Сумма <= 0 — вывести сообщение пользователю через Сообщить("Сумма должна быть больше нуля"); и установить Отказ = Истина; если хотя бы одна строка не прошла проверку — движения по регистру не формировать вообще (проверка выполняется до заполнения Движения.Затраты) Только если все строки прошли проверку — заполнить движения регистра Затраты (как в п.3 предыдущей версии задания), тоже через выборку из результата того же запроса, а не через повторный цикл по табличной части — это закрепляет технику из Задания 2.

### Часть 4. Проверка (10 мин)

- Создать и провести 3–4 документа «Затраты» по разным складам и статьям.
- Открыть регистр через меню «Все функции» → посмотреть таблицу движений, убедиться, что записи соответствуют введённым данным.
- Отменить проведение одного документа — убедиться, что соответствующие движения удаляются из регистра.
